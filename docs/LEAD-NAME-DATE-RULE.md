# 小满线索名称日期规则

## 业务规则

从 `2.0.0-beta.10` 源码起，线索名称中的六位日期按询盘**原始保存时间**确定：

1. 将原始时间换算到固定的北京时间 `Asia/Shanghai`。
2. 北京时间 00:00–17:59:59，名称使用当天日期。
3. 北京时间 18:00–23:59:59，名称使用下一个日历日的日期。
4. 输出 `YYMMDD`；名称中的其他内容沿用本站原映射。

业务含义为“北京时间下午 6 点起计入次日”。实际提交时间不加 18 小时。WordPress 或服务器采用 UTC、纽约或其他时区时，名称仍按同一北京时间边界计算。

## 示例

| 原始提交时间（北京时间） | 名称日期 | 原因 |
| --- | --- | --- |
| 2026-10-06 00:00:00 | `261006` | 当日 18:00 前 |
| 2026-10-06 17:59:59 | `261006` | 分界前一秒 |
| 2026-10-06 18:00:00 | `261007` | 分界开始 |
| 2026-10-06 23:59:59 | `261007` | 当日 18:00 后 |
| 2026-10-07 00:00:00 | `261007` | 新一天 18:00 前 |
| 2026-10-31 18:00:00 | `261101` | 跨月 |
| 2026-12-31 18:00:00 | `270101` | 跨年 |
| 2028-02-28 18:00:00 | `280229` | 闰年次日 |

同一边界对应 UTC `10:00:00`，例如 `2026-10-06 09:59:59 UTC` 使用 `261006`，`2026-10-06 10:00:00 UTC` 使用 `261007`。

## 保存、重试和历史记录

- 保存 UTC、提交时间、备注中的时间及 Google 实际事件时间使用原值；名称日期不用于广告对账的日期列。
- 小满同步失败重试时，每次读取同一个原始保存时间，按上述规则计算。不得使用重试执行时间，也不得在上一次名称日期上再加一天。
- 已成功创建的历史小满客户不重命名、不重新创建；现有 CRM ID、队列状态和防重复机制继续保留。
- 本次方威先行。其他站点和安行在各自迁移核验通过前维持现有线上规则，不因共享源码变化自动覆盖。
- beta.9 中的“原始时间加 12 小时后按 WordPress 时区格式化”属于该历史版本的规则；beta.9 的包、标签和历史报告保留原内容。

## 验证与部署

使用本地合成输入验证分界前一秒、分界时刻、当天末尾、次日零点、跨月、跨年、闰年及不同 WordPress 时区。对同一原始时间多次构建同步载荷，名称日期应相同，原时间与备注不变；测试期间阻断外部请求。

发布 beta.10 时核对插件入口版本、公开源码、签名清单及完整 ZIP 一致。方威部署前备份当前文件；部署后只读回查生效文件与规则。无需为这项规则额外创建测试客户或浏览器转化。

回滚仅恢复经核对的名称日期实现，不覆盖同时期转化修复，不还原整库，不重命名既有成功客户。后续新创建记录将遵循回滚后的名称规则，记录切换时间以便业务识别。
